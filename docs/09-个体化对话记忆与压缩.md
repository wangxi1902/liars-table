# 个体化对话记忆与压缩

这一阶段给每个`LLMAgent`增加独享的有限对话记忆。系统事件流仍然永久保存，只有AI
用于决策的认知副本会遗忘和压缩。

## 1. 三层记忆结构

### 最近完整发言

默认保留最近4条公开发言原文：

```text
#31 P4：……
#34 P5：……
#37 P6：……
#40 P7：……
```

新发言到来后，最旧的一条移出工作记忆并进入压缩摘要。

### 更早发言的压缩摘要

旧发言按说话人合并，只保留：

- 发言次数；
- 来源事件编号；
- 公开指控过谁及次数；
- 声称过什么身份；
- 最近一段截断摘要；
- 当前观察者自己的怀疑分。

因此同一名P2在不同Agent的Prompt中可能拥有不同怀疑分，这体现了个人视角。完整原文
仍在Engine事件流中，可以回放和审计。

### 自己的公开发言与承诺

默认额外保存最近2条自己的完整发言，并长期记录结构化承诺：

```text
#18 自称seer
#27 指控P6
```

这为后续检查无意矛盾、故意欺骗和策略退出条件提供基础。目前只记录，不自动判断
矛盾或创建策略。

## 2. Python基础：容量配置和列表截断

`ConversationMemoryConfig`集中管理容量：

```python
ConversationMemoryConfig(
    recent_speeches=4,
    own_recent_speeches=2,
    max_sources_per_speaker=12,
    max_self_commitments=16,
    excerpt_chars=100,
)
```

配置通过LLMAgent构造函数注入，测试可以使用很小的容量快速触发压缩。配置对象使用
`frozen=True`，一局运行中不会突然改变记忆规则。

## 3. 数据如何流动

```text
Engine产生Spoke(event_id)
        ↓ 可见性裁剪
LLMAgent.observe
        ├─ MemoryStore：通用事件相关度召回
        ├─ Facts：精确票型、身份声称和死亡
        ├─ SuspicionLedger：公开行为怀疑分
        └─ ConversationMemory：最近原文、旧摘要、自我承诺
                ↓
LangGraph.prepare_context
                ↓
Prompt
```

四种认知组件各自承担不同职责，没有用一个巨大的“记忆类”包办全部功能。

## 4. 为什么公开发言不再由MemoryStore重复召回

`MemoryStore`原本也会召回发言。接入`ConversationMemory`后，如果两边同时输出，同一句
话会在Prompt中重复出现，浪费Token并夸大该发言的重要性。

现在公开发言由`ConversationMemory`独占；`MemoryStore`继续提供夜间私有信息、死亡和
其他相关事件。

## 5. 旧发言为什么仍可引用

压缩摘要保留`source_summaries`：事件编号和截断公开原文。生成安全思考依据时，当前
时间线白名单会与个人压缩记忆中的公开编号合并。因此AI可以引用已经离开最近窗口、
但自己仍然记得的旧发言，同时无法引用从未观察到的私有事件。

## 6. 当前压缩不是LLM摘要

第一版只做确定性压缩：读取已有`claims`、身份声称、来源编号和截断文本。它不能准确
理解“虽然但是”、讽刺、复杂逻辑和隐含立场。

先使用确定性实现的原因是：

- Mock和测试不依赖真实API；
- 相同事件产生相同摘要；
- 信息隔离容易验证；
- 后续可以在接口不变的情况下替换为模型摘要或向量检索。

## 7. 学习检查点

**问题1：为什么Engine仍要保存全部原始事件？**

参考答案：AI遗忘是认知模拟，系统事件流是审计事实。回放、测试、赛后分析和反事实
推演都需要完整记录，不能跟着AI一起遗忘。

**问题2：为什么自己的发言要额外保存？**

参考答案：下一轮需要检查自己公开过的身份、指控和承诺，才能区分无意矛盾与计划内
欺骗。普通最近窗口溢出后不能把这些关键信息全部丢掉。

**问题3：为什么摘要必须保留来源事件编号？**

参考答案：没有来源编号就无法检查摘要是否歪曲原话，也无法在思考卡片、RAG和回放中
跳回原始事件。

**问题4：为什么不直接让LLM为9名玩家每条发言都生成摘要？**

参考答案：那会显著增加调用次数、成本和延迟，也让测试依赖网络。第一版先稳定数据
边界和信息隔离，再选择只在记忆溢出或重要事件上调用模型。

可选练习：把`recent_speeches`改为2，依次写入3条发言，预测哪两条保留原文、哪一条
进入哪个玩家的压缩摘要，并用单元测试验证。

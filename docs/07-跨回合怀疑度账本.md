# 跨回合怀疑度账本

上一阶段的怀疑度来自模型单次输出。本阶段把它改成每个Agent独享、跨回合持续更新的
Python账本。模型可以读取和解释账本，但不能直接覆盖累计分数。

## 1. 先理解“有状态对象”

`SuspicionLedger`在创建`LLMAgent`时创建，并一直存活到本局结束：

```text
创建P1 Agent
  └─ 创建P1的SuspicionLedger
       ├─ 观察第1轮发言并更新
       ├─ 观察第1轮投票并更新
       ├─ 第2轮决策时继续读取同一份对象
       └─ 对局结束后随Agent一起释放
```

它不同于函数里的临时变量。`observe()`修改的是同一个账本对象，因此下一轮仍能看到
上一轮分数和原因。

## 2. 为什么先用确定性规则

第一版规则都是普通Python条件分支：

| 公开行为 | 分数变化 |
|---|---:|
| 指控他人但没有引用事件 | +7 |
| 指控时引用可核验公开事件 | -2 |
| 与其他玩家出现身份声称冲突 | 新声称者+10，已有声称者+5 |
| 投票前没有公开怀疑目标 | +4 |
| 与上一轮相比改变投票目标 | +5 |

优点是同一事件一定产生同一结果，容易单测、复盘和解释。缺点是这些只是启发式，不是
统计模型，也不是经过真实对局校准的狼人概率。

## 3. 为什么observe需要event_id

原接口是：

```python
observe(event, round_no)
```

现在扩展为：

```python
observe(event, round_no, event_id=None)
```

`event_id`是事件在引擎事件流中的全局编号。账本变化保存这个编号，前端才能显示：

```text
#27 · 投票前没有公开表达对目标的怀疑 +4
P6 投给 P2
```

参数默认是`None`，这样单独测试Agent时仍可省略；真实Engine广播一定传入编号。

## 4. 信息隔离没有改变

事件仍然先经过`Engine._audience()`裁剪，再调用Agent的`observe()`。账本只处理
`Spoke`和`Voted`两个公开事件类型，预言家查验、狼人夜聊和女巫操作不会改变公开
怀疑分，也不会进入前端卡片。

每个Agent拥有自己的账本，观察者本人分数固定为0，不会因为自己的发言给自己加分。

## 5. 模型和账本谁拥有最终分数

模型仍可在`basis`中提出关注对象，但安全转换时执行：

```text
展示分数 = SuspicionLedger.score(seat)
```

而不是使用模型提交的`suspicion`。例如模型输出99，但账本根据公开行为算出42，前端
显示42。若模型没有返回关注对象，后端会选择当前账本分最高的存活玩家作为展示对象。

## 6. Prompt如何使用账本

发言和投票前，Prompt会收到最多四名玩家的账本摘要：

```text
【怀疑度账本】分数只是公开行为信号，不等于真实身份概率
  老K：42/100（+7 公开指控他人但没有引用事件依据）
  小北：35/100（暂无显著公开信号）
```

这相当于把普通Python状态转换成模型可以阅读的文本。LangGraph负责在准备上下文节点
中装配它，但分数计算本身不依赖LangGraph或LLM。

## 7. 当前局限

- 改票不一定可疑，可能是听完新发言后的合理修正；当前规则无法区分。
- “有引用”不代表引用真的支持结论；当前只验证编号存在和可见。
- 初始35分和每次增减值是人工设定，尚未用固定种子对局集校准。
- 已出局玩家的真实身份不会反向修正之前判断，反思节点尚未实现。
- 账本仍在内存中，没有写入数据库。

因此界面使用“狼人嫌疑”而不是“狼人概率”。

## 8. 学习检查点

1. 为什么账本要挂在`LLMAgent`实例上，而不能在`decide()`里每次新建？
2. 为什么模型可以选择关注谁，却不能直接决定累计分数？
3. `event_id=None`解决了什么测试和兼容问题？
4. 为什么预言家的私有查验不能直接改变公开怀疑卡片？

可选练习：增加“连续两轮投给同一目标且始终没有公开解释”的原因码和单元测试。先写
测试，再实现规则，并思考它是否可能误伤正常玩家。

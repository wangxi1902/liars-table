## 三、Python 概念对照表

### 1. 类（class）和 `self`

看 `core/state.py` 的 `GameState`：

```python
@dataclass
class GameState:
    alive: set[str] = field(default_factory=set)

    def alive_sorted(self) -> list[str]:
        return sorted(self.alive, key=seat_key)
```

- `class` 定义了一个"类型"，`GameState()` 创建一个"实例"。
- `self` 就是"当前这个实例"，等价于 Java 里的 `this`，但**必须显式写在参数第一位**。
- `def alive_sorted(self)` 是实例方法：调用时写 `state.alive_sorted()`，Python 自动把 `state` 传给 `self`。
- 注意 `self.alive`（实例属性）和 `seat_key`（模块级函数）的区别：前者要通过 `self.` 访问。

### 2. `@dataclass`：自动生成样板代码

```python
@dataclass(frozen=True, slots=True)
class WolfKilled(Event):
    target: str
```

等价于手写 `__init__`、`__repr__`、`__eq__`。三个参数的含义：

| 参数 | 作用 | 为什么这里要它 |
|---|---|---|
| `frozen=True` | 创建后不能改属性 | 事件必须不可变，否则历史会被篡改 |
| `slots=True` | 只能有声明过的属性 | 省内存；写错属性名立刻报错，而不是悄悄多一个字段 |
| （默认） | 生成 `__eq__` | 两个事件字段相同就相等，方便测试断言 |

对比一下不用 dataclass 的写法，你就知道它省了多少：

```python
class WolfKilled:
    def __init__(self, target: str) -> None:
        self.target = target
    def __repr__(self) -> str: ...
    def __eq__(self, other) -> bool: ...
```

### 3. 类型注解

```python
def _pick(self, seat: str, kind: str, legal: Sequence[str]) -> str:
```

- `seat: str` 是参数注解，`-> str` 是返回值注解。
- **注解不会在运行时强制检查**，它是给人和工具（IDE、mypy）看的。
- 复杂类型的读法：
  - `list[tuple[str, str]]` = 列表，元素是二元组
  - `dict[str, Role]` = 键是字符串、值是 Role 的字典
  - `Camp | None` = 要么是 Camp，要么是 None（等价于旧写法 `Optional[Camp]`）
  - `Sequence[str]` = "任何能按下标遍历的字符串序列"（list/tuple 都行），比写死 `list` 更灵活

### 4. Enum / StrEnum

`core/roles.py` 里：

```python
class Role(StrEnum):
    WEREWOLF = "werewolf"
```

- 用常量代替裸字符串，写错 `Role.WEREWOLF` 会立刻 AttributeError，而不是运行到一半才发现。
- `StrEnum` 继承自 `str`，所以 `Role.WEREWOLF == "werewolf"` 为真，可以直接 `json.dumps`。
- 用 `is` 比较枚举（`self.roles[s] is Role.WEREWOLF`），比 `==` 更快也更明确。

### 5. 函数、默认参数、可变默认值的坑

```python
def __init__(self, seed: int = 0, on_event: Callable[[ev.Event], None] | None = None):
```

- `= 0` 是默认参数，调用时可以省略。
- **绝对不要**写 `def f(x, items=[])`——默认值只在函数定义时创建一次，所有调用会共享同一个列表。
  所以 `GameState` 里用 `field(default_factory=set)`，每次实例化都新建一个。

### 6. Protocol：不继承也能"实现接口"

```python
class Agent(Protocol):
    def decide(self, request: DecisionRequest) -> Decision: ...
```

只要你的类有 `decide` 方法，它就自动是 Agent，不需要 `class MyAgent(Agent)`。
这叫结构化子类型。好处是测试时随手写个假 agent 就能用，不用改动生产代码。

### 7. 推导式与生成器表达式

```python
prey = [s for s in self.state.alive_sorted() if s not in wolves]
```

读法："对 alive_sorted() 里每个 s，如果 s 不在 wolves 里，就收集起来"。
等价于一个 for 循环 + append，但更短、更快。

`Counter` 也是常用工具（`engine._majority` 里）：

```python
counts = Counter(votes.values())   # {"P3": 2, "P5": 1}
best = max(counts.values())
```

### 8. 异常与容错

```python
if not legal:
    raise RuntimeError(f"no legal target for {kind!r} ({seat})")
```

- `raise` 主动抛异常，让错误尽早暴露，而不是返回一个 `None` 让上层慢慢炸。
- 但**面对 LLM 时相反**：`_pick` 里对非法目标不抛异常，而是随机兜底——
  因为模型输出不可控是常态，不能让它把整局搞崩。这是"内部严格、边界宽容"。

## 四、三个核心设计（比语法更重要）

### 1. 事件溯源（Event Sourcing）

```
不信：state.alive.remove("P3")
相信：events.append(PlayerDied("P3"))  然后 state = fold(events)
```

为什么值得？因为它同时解决了四件事：回放、复盘、调试、反事实推演。
面试时讲这个，比讲"我用了 LangChain"有价值得多。

### 2. 规则与智能分离

流程写在 `engine.py` 里，是确定的代码；模型只负责"刀谁、说什么"。
模型输出再离谱，也只能在合法集合里选，流程永远不会乱。

### 3. 纯函数

`core/rules.py` 里的函数不读写文件、不发网络请求、不看时间，只依赖入参。
好处是**测试极其便宜**（`test_rules.py` 跑完只要几毫秒），推理也简单。

## 五、代码规范（照着做就不会被骂）

| 规范 | 本项目做法 |
|---|---|
| 命名 | 变量/函数 `snake_case`，类 `PascalCase`，常量 `UPPER_CASE` |
| 行宽 | 100 字符（`pyproject.toml` 里配的） |
| 文档字符串 | 每个模块、每个公开类/函数都写，中文 |
| 类型注解 | 所有函数签名都写，`from __future__ import annotations` 放第一行 |

| 提交信息 | `feat:` / `fix:` / `docs:` / `refactor:` 开头 |
| 改完必做 | `uv run ruff check .` + `uv run pytest` |

这两个命令就是你的"编译检查"。养成习惯：**提交前必跑**。

## 七、下一步：异步（async）

现在引擎是同步的：9 个 agent 依次说话，一次只有一个在等 LLM。
真实情况是 9 个请求可以同时发出去，总耗时从 `9 × 2s` 降到 `约 2s`。

v0.2 会用到：

```python
async def _speak_all(self, seats: list[str]) -> list[Decision]:
    tasks = [self._ask_async(seat, "speech") for seat in seats]
    return await asyncio.gather(*tasks)   # 一起等，不是一个个等
```

到时候我会专门写一节讲清楚：协程、`await`、`asyncio.gather`、以及"什么时候**不该**用异步"。
现在先把同步版本读透，异步本身只是"等 IO 的时候切去做别的"，概念没那么玄。
